# 플랫폼 비즈니스 모델

라이브 커머스 플랫폼의 돈과 물건의 흐름, 수익 구조, 상품 구분, 월 청구 방식, 그리고 여기서 나오는 어드민 화면 범위를 정리한 문서입니다. 아직 구현된 코드는 없고, 이후 어드민과 정산 기능을 만들 때의 기준으로 씁니다.

- 작성일: 2026-11-23 (같은 날 공급 상품의 발송 주체와 판매 확정 기준을 반영해 개정)
- 상태: 초안. 7장의 질문이 정해지면 이 문서를 먼저 고칩니다.
- 관련 문서: [스토어 설정](../research/livemarket/store-settings.md) (셀러가 바꾸는 값 목록)

## 1. 돈과 물건의 흐름

### 돈
- 고객은 **셀러 계좌로 직접 입금**합니다 (무통장입금).
- **플랫폼은 고객의 돈을 받지 않습니다.** 결제 대금을 보관하거나 셀러에게 정산해 주는 단계가 없습니다.
- **입금 확인은 셀러가 합니다.** 셀러가 자기 계좌의 입금 내역을 보고 주문을 결제완료로 바꿉니다.
- 플랫폼이 받는 돈은 셀러에게 매달 청구하는 금액뿐입니다 (4장).

### 물건
- 셀러 자체 상품은 셀러가 준비해서 고객에게 발송합니다.
- 운영자 공급 상품도 **셀러가 고객에게 발송**합니다. 운영자가 물건을 셀러에게 먼저 넘기고(공급 출고), 셀러가 보유한 재고에서 발송합니다.
- 안 팔린 공급 상품은 **운영자가 회수**합니다.

```
돈:    고객 ──(상품 대금 입금)──▶ 셀러 계좌
       셀러 ──(월 청구 금액 납부)──▶ 운영자

물건:  운영자 ──(공급 출고)──▶ 셀러 ──(발송)──▶ 고객
       운영자 ◀──(안 팔린 물건 회수)── 셀러
```

## 2. 플랫폼 수익

| 수익원 | 내용 |
| --- | --- |
| 월 이용료 | 셀러가 플랫폼을 쓰는 대가로 매달 내는 고정 금액. 플랜에 따라 다릅니다 |
| 상품 공급 마진 | 운영자가 셀러에게 상품을 공급하고 받는 공급가에 포함된 마진 |

## 3. 상품 구분

| 구분 | 설명 | 발송 | 플랫폼 청구 |
| --- | --- | --- | --- |
| 셀러 자체 상품 | 셀러가 직접 준비해 등록하는 상품 | 셀러 | 없음 (월 이용료만) |
| 운영자 공급 상품 | 운영자가 공급하고 셀러가 자기 스토어에서 파는 상품 | 셀러 (운영자에게 받은 재고에서) | 판매 확정 수량 × 공급가 |

운영자 공급 상품에는 아래 값이 있습니다.

| 값 | 설명 |
| --- | --- |
| 공급가 | 셀러가 운영자에게 내는 단가. **고객에게는 공개하지 않습니다** |
| 최저 판매가 | 셀러가 고객에게 팔 수 있는 가장 낮은 가격 |
| 재고 | 운영자가 가지고 있어 셀러에게 넘길 수 있는 수량. 셀러에게 넘긴 뒤의 수량은 아래 "셀러 보유 재고"로 따로 봅니다 |

셀러의 몫은 고객 판매가에서 공급가를 뺀 금액입니다. 판매가는 최저 판매가 이상에서 셀러가 정합니다.

### 판매 확정
- 공급 상품의 판매는 **발송 처리 시점**에 확정됩니다. 기준은 **송장번호 입력**입니다.
- 주문이 들어오거나 입금이 확인된 것만으로는 판매로 세지 않습니다.

### 셀러 보유 재고

```
셀러 보유 재고 = 넘긴 수량 − 발송 수량 − 회수 수량
```

| 수량 | 늘어나는 때 |
| --- | --- |
| 넘긴 수량 | 운영자가 공급 출고를 기록할 때 |
| 발송 수량 | 셀러가 발송 처리(송장번호 입력)할 때 |
| 회수 수량 | 운영자가 회수 처리할 때 |

- 플랫폼이 공급 상품별, 셀러별로 **자동 계산**합니다. 사람이 직접 입력하는 값이 아닙니다.
- 계산된 수량을 셀러가 실제로 가진 **실물 수량과 대조**할 수 있게 합니다.

## 4. 월 청구

```
월 청구 금액 = 월 이용료 + (공급 상품 판매 수량 × 공급가) − 취소·반품분
```

- **공급 대금은 팔린 만큼만 청구합니다.** 셀러에게 물건을 넘긴 것만으로는 청구하지 않고, 안 팔린 물건은 회수합니다.
- 판매 수량은 판매가 확정된 수량, 즉 **발송 처리(송장번호 입력)된 공급 상품 수량**입니다.
- 셀러 자체 상품의 판매는 청구 금액에 영향을 주지 않습니다.
- 발송 전에 취소된 주문은 판매로 확정된 적이 없으므로 처음부터 판매 수량에 들어가지 않습니다. 취소·반품분으로 빼는 것은 발송 처리 뒤에 취소·반품된 수량 × 공급가입니다.
- 플랫폼은 고객 결제에 관여하지 않으므로, 청구 금액은 셀러가 운영자에게 따로 납부하고 운영자가 수금 여부를 체크합니다.

예시 (숫자는 설명용입니다):

| 항목 | 계산 | 금액 |
| --- | --- | --- |
| 월 이용료 | | 50,000원 |
| 공급 상품 A | 발송 30개 × 공급가 5,000원 | 150,000원 |
| 공급 상품 B | 발송 10개 × 공급가 12,000원 | 120,000원 |
| 취소·반품 | 상품 A 발송 후 반품 2개 × 5,000원 | −10,000원 |
| **월 청구 금액** | | **310,000원** |

같은 달 상품 A를 50개 넘겨받았고 회수가 없었다면, 셀러 보유 재고는 50 − 30 − 0 = 20개이고 이 20개는 청구되지 않습니다.

## 5. 어드민 화면

### 운영자 어드민

| 화면 | 하는 일 |
| --- | --- |
| 공급 상품 관리 | 공급 상품 등록·수정, 공급가·최저 판매가·재고 관리 |
| 공급 출고 기록 | 어느 셀러에게 어떤 공급 상품을 몇 개 넘겼는지 기록 (넘긴 수량) |
| 셀러별 보유 재고 | 셀러마다 공급 상품별 넘긴 수량·발송 수량·회수 수량과 계산된 보유 재고 확인, 실물 대조 |
| 회수 처리 | 안 팔린 공급 상품을 셀러에게서 회수한 수량 기록 (회수 수량) |
| 셀러별 월 청구서 / 수금 체크 | 셀러마다 월 청구 금액과 내역 확인, 납부 여부 체크 |
| 이용료 플랜 | 월 이용료 플랜 관리, 셀러별 플랜 지정 |
| 셀러 승인 | 입점 신청한 셀러 승인 |

### 셀러 어드민

| 화면 | 하는 일 |
| --- | --- |
| 주문 목록 | 들어온 주문서 확인 |
| 입금 확인 | 계좌 입금 내역을 보고 주문을 결제완료로 변경 |
| 발송 처리 | 결제완료 주문에 송장번호를 입력해 발송 처리. 공급 상품은 이때 판매가 확정되고 보유 재고가 줄어듭니다 |
| 내 공급 재고 | 공급 상품별 받은 수량, 판 수량, 남은 수량 확인 |
| 스토어 설정 | 결제 기한, 배송비, 입금 계좌, 공지 등 ([스토어 설정 문서](../research/livemarket/store-settings.md)의 항목) |
| 내 매출 | 스토어의 판매 금액 확인 |
| 이번 달 청구 예정 금액 | 이번 달 이용료와 공급 상품 판매분으로 계산한 청구 예정 금액 |

## 6. 아직 정하지 않은 것

지금은 없습니다. 처음에 미정이던 두 항목은 2026-11-23에 아래와 같이 정해져 본문에 반영했습니다.

| 항목 | 결정 | 반영한 곳 |
| --- | --- | --- |
| 공급 상품의 발송 주체 | 셀러. 운영자가 물건을 먼저 넘기고 셀러가 고객에게 발송 | 1장, 3장 |
| 공급 상품의 판매 확정 기준 | 발송 처리 시점 (송장번호 입력 기준) | 3장, 4장 |

## 7. 구현 전에 추가로 확인할 것

문서를 정리하면서 생긴 질문입니다. 결정된 사항이 아니라 확인이 필요한 목록입니다.

### 이번 결정으로 답이 나온 것
- **재고 공유** (한 공급 상품을 여러 셀러가 팔 때 재고를 함께 쓰는지): 운영자가 셀러에게 물건을 실제로 넘기므로, 넘긴 뒤의 재고는 셀러별로 나뉩니다. 함께 쓰는 것은 아직 넘기지 않은 운영자 재고뿐입니다.
- **발송 전 취소의 청구 처리**: 판매 확정이 발송 시점이라, 발송 전에 취소된 주문은 청구 대상이 된 적이 없습니다. 따로 뺄 것이 없습니다.

### 아직 남은 것
- **발송 후 반품, 월을 넘긴 반품**: 발송 처리한 달에 청구한 뒤 다음 달에 반품되면 다음 달 청구서에서 빼는지, 지난 청구서를 고치는지.
- **반품된 물건의 재고**: 고객이 반품한 공급 상품이 셀러 보유 재고로 돌아오는지. 지금의 보유 재고 공식(넘긴 수량 − 발송 수량 − 회수 수량)에는 반품 수량이 없습니다.
- **실물과 차이가 날 때**: 대조 결과 계산된 보유 재고와 실물이 다르면(분실, 파손 등) 누가 부담하고 어떻게 기록하는지.
- **공급가 변경**: 공급가가 바뀌었을 때 어느 시점의 공급가로 청구하는지 (물건을 넘긴 시점 / 발송 처리 시점).
- **최저 판매가 적용 범위**: 셀러가 최저 판매가보다 낮게 등록하지 못하게 막는지, 타임딜·쿠폰 할인에도 적용하는지.
- **보유 재고보다 많이 팔렸을 때**: 셀러 보유 재고를 넘는 주문을 막는지, 받아 두고 추가 출고를 기다리는지.
- **미납 처리**: 셀러가 청구 금액을 내지 않았을 때 어떻게 하는지 (스토어 이용 제한 등).
- **입금 확인 방식**: 셀러가 수동으로만 확인하는지. 현재 주문 화면에는 고객의 "입금완료 확인요청" 버튼이 있고, 이 요청이 셀러 어드민의 입금 확인 화면으로 이어집니다.
