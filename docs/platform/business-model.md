# 플랫폼 비즈니스 모델

라이브 커머스 플랫폼의 돈 흐름, 수익 구조, 상품 구분, 월 청구 방식, 그리고 여기서 나오는 어드민 화면 범위를 정리한 문서입니다. 아직 구현된 코드는 없고, 이후 어드민과 정산 기능을 만들 때의 기준으로 씁니다.

- 작성일: 2026-11-23
- 상태: 초안. "아직 정하지 않은 것"이 정해지면 이 문서를 먼저 고칩니다.
- 관련 문서: [스토어 설정](../research/livemarket/store-settings.md) (셀러가 바꾸는 값 목록)

## 1. 돈의 흐름

- 고객은 **셀러 계좌로 직접 입금**합니다 (무통장입금).
- **플랫폼은 고객의 돈을 받지 않습니다.** 결제 대금을 보관하거나 셀러에게 정산해 주는 단계가 없습니다.
- **입금 확인은 셀러가 합니다.** 셀러가 자기 계좌의 입금 내역을 보고 주문을 결제완료로 바꿉니다.
- 플랫폼이 받는 돈은 셀러에게 매달 청구하는 금액뿐입니다 (3장).

```
고객 ──(상품 대금 입금)──▶ 셀러 계좌
셀러 ──(월 청구 금액 납부)──▶ 플랫폼 운영자
```

## 2. 플랫폼 수익

| 수익원 | 내용 |
| --- | --- |
| 월 이용료 | 셀러가 플랫폼을 쓰는 대가로 매달 내는 고정 금액. 플랜에 따라 다릅니다 |
| 상품 공급 마진 | 운영자가 셀러에게 상품을 공급하고 받는 공급가에 포함된 마진 |

## 3. 상품 구분

| 구분 | 설명 | 플랫폼 청구 |
| --- | --- | --- |
| 셀러 자체 상품 | 셀러가 직접 준비해 등록하는 상품 | 없음 (월 이용료만) |
| 운영자 공급 상품 | 운영자가 공급하고 셀러가 자기 스토어에서 파는 상품 | 판매 수량 × 공급가 |

운영자 공급 상품에는 아래 값이 있습니다.

| 값 | 설명 |
| --- | --- |
| 공급가 | 셀러가 운영자에게 내는 단가. **고객에게는 공개하지 않습니다** |
| 최저 판매가 | 셀러가 고객에게 팔 수 있는 가장 낮은 가격 |
| 재고 | 운영자가 공급할 수 있는 수량 |

셀러의 몫은 고객 판매가에서 공급가를 뺀 금액입니다. 판매가는 최저 판매가 이상에서 셀러가 정합니다.

## 4. 월 청구

```
월 청구 금액 = 월 이용료 + (공급 상품 판매 수량 × 공급가) − 취소·반품분
```

- 셀러 자체 상품의 판매는 청구 금액에 영향을 주지 않습니다.
- 취소·반품분은 취소되거나 반품된 공급 상품의 수량 × 공급가입니다.
- 플랫폼은 고객 결제에 관여하지 않으므로, 청구 금액은 셀러가 운영자에게 따로 납부하고 운영자가 수금 여부를 체크합니다.

예시 (숫자는 설명용입니다):

| 항목 | 계산 | 금액 |
| --- | --- | --- |
| 월 이용료 | | 50,000원 |
| 공급 상품 A | 30개 × 공급가 5,000원 | 150,000원 |
| 공급 상품 B | 10개 × 공급가 12,000원 | 120,000원 |
| 취소·반품 | 상품 A 2개 × 5,000원 | −10,000원 |
| **월 청구 금액** | | **310,000원** |

## 5. 어드민 화면

### 운영자 어드민

| 화면 | 하는 일 |
| --- | --- |
| 공급 상품 관리 | 공급 상품 등록·수정, 공급가·최저 판매가·재고 관리 |
| 셀러별 월 청구서 / 수금 체크 | 셀러마다 월 청구 금액과 내역 확인, 납부 여부 체크 |
| 이용료 플랜 | 월 이용료 플랜 관리, 셀러별 플랜 지정 |
| 셀러 승인 | 입점 신청한 셀러 승인 |

### 셀러 어드민

| 화면 | 하는 일 |
| --- | --- |
| 주문 목록 | 들어온 주문서 확인 |
| 입금 확인 | 계좌 입금 내역을 보고 주문을 결제완료로 변경 |
| 발송 처리 | 결제완료 주문의 발송 처리 |
| 스토어 설정 | 결제 기한, 배송비, 입금 계좌, 공지 등 ([스토어 설정 문서](../research/livemarket/store-settings.md)의 항목) |
| 내 매출 | 스토어의 판매 금액 확인 |
| 이번 달 청구 예정 금액 | 이번 달 이용료와 공급 상품 판매분으로 계산한 청구 예정 금액 |

## 6. 아직 정하지 않은 것

| 항목 | 선택지 | 영향 |
| --- | --- | --- |
| 공급 상품의 판매 확정 기준 | 입금 확인 시점 / 발송 시점 | 월 청구의 "판매 수량"을 언제 세는지, 재고를 언제 차감하는지, 어느 달 청구서에 들어가는지가 달라집니다 |
| 공급 상품의 발송 주체 | (미정) | 누가 고객에게 발송하는지에 따라 발송 처리 화면이 어느 어드민에 필요한지, 재고를 어디서 관리하는지가 달라집니다 |

## 7. 구현 전에 추가로 확인할 것

위 내용을 정리하면서 생긴 질문입니다. 결정된 사항이 아니라 확인이 필요한 목록입니다.

- **월을 넘긴 취소·반품**: 이미 청구한 달의 판매가 다음 달에 취소·반품되면 다음 달 청구서에서 빼는지, 지난 청구서를 고치는지.
- **최저 판매가 적용 범위**: 셀러가 최저 판매가보다 낮게 등록하지 못하게 막는지, 타임딜·쿠폰 할인에도 적용하는지.
- **공급가 변경**: 공급가가 바뀌었을 때 이미 들어온 주문에는 주문 시점의 공급가를 쓰는지.
- **재고 공유**: 한 공급 상품을 여러 셀러가 팔 때 재고를 함께 쓰는지, 셀러별로 나누는지.
- **미납 처리**: 셀러가 청구 금액을 내지 않았을 때 어떻게 하는지 (스토어 이용 제한 등).
- **입금 확인 방식**: 셀러가 수동으로만 확인하는지. 현재 주문 화면에는 고객의 "입금완료 확인요청" 버튼이 있고, 이 요청이 셀러 어드민의 입금 확인 화면으로 이어집니다.
