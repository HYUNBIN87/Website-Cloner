# 운영자 어드민 (초안)

플랫폼 운영자가 공급 상품을 관리하고, 셀러에게 넘긴 물건과 회수한 물건을 기록하고, 셀러별 월 청구서를 보고 수금을 체크하고, 이용료 플랜과 셀러 승인을 관리하는 화면입니다.

- 작성일: 2026-11-23
- 상태: **초안**. 원본 사이트의 어드민을 따라 만든 것이 아니라 [비즈니스 모델](business-model.md) 문서를 기준으로 새로 만든 것입니다.
- 경로: `/operator-admin` 아래
- 디자인: [셀러 어드민 초안](seller-admin.md)과 같은 틀(500px 컬럼, 카드, 상태 칩, 버튼)을 그대로 씁니다.

## 지금 되는 것과 안 되는 것

- **전부 가짜 데이터입니다.** 셀러, 대표자 이름, 연락처, 공급가, 수량, 플랜 금액 모두 지어낸 값입니다.
- **이 브라우저의 localStorage에만 저장됩니다** (`livemarket-clone-platform`). 서버가 없어 다른 기기에서는 보이지 않습니다.
- **운영자 로그인이 없습니다.** 주소를 아는 누구나 열 수 있습니다.
- **셀러 어드민과 같은 데이터를 씁니다.** 공급 상품, 넘긴 수량, 회수 수량, 플랜은 한 저장소에 있고 두 어드민이 함께 읽습니다. 그래서 숫자가 서로 맞습니다 (아래 "셀러 어드민과 맞물리는 숫자").

## 화면 구성

| 메뉴 | 경로 | 하는 일 |
| --- | --- | --- |
| 공급 상품 | `/operator-admin` | 공급 상품 등록, 공급가·최저 판매가·재고 관리 |
| 공급 출고 | `/operator-admin/handovers` | 셀러에게 넘긴 수량 기록, 셀러별 보유 재고 확인 |
| 회수 | `/operator-admin/recoveries` | 안 팔린 물건을 돌려받은 수량 기록 |
| 월 청구서 | `/operator-admin/invoices` | 셀러별 월 청구 금액과 수금 체크 |
| 이용료 플랜 | `/operator-admin/plans` | 플랜별 월 이용료, 결제일, 미납 시 처리 |
| 셀러 승인 | `/operator-admin/sellers` | 가입 신청 승인·반려, 플랜 지정 |

### 1. 공급 상품 관리
- 상품별로 공급가(고객 비공개), 최저 판매가, 운영자 재고를 고칩니다. 값을 고치면 바로 저장됩니다.
- 상품마다 "운영자 재고 N개 · 셀러 보유 합계 N개"를 보여 줍니다.
- 최저 판매가가 공급가보다 낮으면 경고합니다. 새 상품 등록 때는 이 경우 등록을 막습니다.
- 상품 등록: 상품명, 공급가, 최저 판매가, 재고. 사진 등록은 없어 기본 아이콘으로 표시됩니다.
- 공급가는 운영자 어드민과 셀러 어드민에만 나옵니다. 고객 화면에는 나오지 않습니다.
- 새로 등록한 공급 상품은 셀러에게 출고한 뒤, 셀러가 셀러 어드민의 "상품" 화면에서 스토어에 등록해야 고객 화면에 나타납니다.

### 2. 공급 출고 기록
- 셀러(승인된 셀러만), 공급 상품, 수량을 골라 "출고 기록"을 누릅니다.
- 넘긴 만큼 **운영자 재고가 줄고**, 그 셀러의 **넘긴 수량(셀러 어드민의 "받은 수량")이 늘어납니다.** 운영자 재고보다 많이는 넘길 수 없습니다.
- 넘긴 것만으로는 청구하지 않습니다. 청구는 셀러가 발송 처리한 수량 기준입니다.
- **셀러별 보유 재고**: 셀러마다 공급 상품별 넘긴 수량, 발송 수량, 회수 수량, 보유 재고를 보여 줍니다. 보유 재고 = 넘긴 수량 − 발송 수량 − 회수 수량이고 자동 계산입니다. 실물 대조는 이 숫자와 셀러가 실제로 가진 수량을 비교해서 합니다.
- 출고 내역: 날짜, 셀러, 상품, 수량 (최근 순).

### 3. 회수 처리
- 셀러와 그 셀러가 보유한 공급 상품, 수량을 골라 "회수 기록"을 누릅니다.
- 회수한 만큼 그 셀러의 **회수 수량이 늘고 보유 재고가 줄며**, 물건은 **운영자 재고로 돌아옵니다.** 셀러 보유 재고보다 많이는 회수할 수 없습니다.
- 회수 내역: 날짜, 셀러, 상품, 수량 (최근 순).

### 4. 셀러별 월 청구서
- 월 청구 금액 = 월 이용료 + 공급 대금(발송 수량 × 공급가) − 취소·반품분.
- 지난달(확정)과 이번 달(예정)을 바꿔 볼 수 있습니다.
- 지난달: 맨 위에 청구 합계, 수금 완료, 미수금. 셀러마다 내역과 "수금 완료" 체크박스가 있고, 체크한 시각이 남습니다. 미수금인 셀러에는 결제일과 미납 시 처리(플랜 설정)가 표시됩니다.
- 이번 달: 지금까지 발송된 수량으로 계산한 예정 금액입니다. 수금 체크는 없습니다.
- 그 달이 끝나기 전에 승인된 셀러만 청구 대상입니다.
- 취소·반품분은 항상 0원입니다. 발송 후 반품 기능이 아직 없습니다.

### 5. 이용료 플랜
- 플랜별로 이름, 월 이용료, 결제일(매월 N일, 1~28), 미납 시 처리(결제일 뒤 며칠 후에 "안내만 보냄" 또는 "스토어 이용 제한")를 고칩니다. 바로 저장됩니다.
- 플랜을 쓰는 셀러 수를 표시합니다. "플랜 추가"로 새 플랜을 만듭니다.
- **미납 시 처리는 표시만 합니다.** 결제일이 지나도 실제로 안내를 보내거나 스토어를 제한하지 않습니다.

### 6. 셀러 승인
- 승인 대기 / 승인된 셀러 / 반려로 나눠 보여 줍니다. 스토어 이름, 대표자, 연락처, 판매 품목, 신청 시각.
- 승인 대기: 플랜을 고르고 "승인" 또는 "반려". 승인하면 공급 출고와 청구 대상이 됩니다.
- 승인된 셀러의 플랜은 여기서 바꿉니다.
- 가입 신청을 받는 화면(셀러가 신청서를 쓰는 쪽)은 없습니다. 신청 2건은 가짜 데이터입니다.

## 셀러 어드민과 맞물리는 숫자

| 운영자 어드민 | 셀러 어드민 (데모샵) | 연결 방식 |
| --- | --- | --- |
| 공급 출고의 넘긴 수량 | 공급 재고의 받은 수량 | 같은 출고 기록의 합계 |
| 회수 처리의 회수 수량 | 공급 재고의 회수 수량 | 같은 회수 기록의 합계 |
| 셀러별 보유 재고의 발송 수량 | 공급 재고의 판 수량 | 셀러 어드민에서 발송 처리한 주문의 수량 |
| 셀러별 보유 재고 | 공급 재고의 남은 수량 | 같은 계산식 |
| 공급 상품의 공급가·최저 판매가 | 공급 재고의 공급가·최저 판매가 | 같은 상품 데이터 |
| 이번 달 청구서 (데모샵) | 매출의 이번 달 청구 예정 금액 | 같은 계산 함수 |
| 이용료 플랜의 월 이용료·결제일 | 매출의 월 이용료·결제일 | 셀러에게 지정된 플랜 |

- 데모샵의 발송 수량은 셀러 어드민의 실제(가짜) 주문에서 셉니다. 셀러 어드민에서 발송 처리를 하면 운영자 쪽 보유 재고와 이번 달 청구서가 함께 바뀝니다.
- 다른 셀러(예시마켓, 샘플상회)는 주문 데이터가 없어 발송 수량이 고정된 가짜 값입니다.

기본값으로 되돌리려면 브라우저 저장소에서 `livemarket-clone-platform`을 지웁니다. 화면에 되돌리기 버튼은 없습니다.

## 아직 없는 것, 정해야 할 것

- **기록 수정·삭제**: 출고나 회수를 잘못 기록했을 때 고치거나 지우는 기능이 없습니다. 상품 삭제, 플랜 삭제도 없습니다.
- **공급가 변경 시점**: 청구서는 현재 공급가로 계산합니다. 공급가를 바꾸면 이미 발송된 수량의 청구 금액도 바뀝니다. 어느 시점의 공급가로 청구할지는 비즈니스 모델 7장의 남은 질문입니다.
- **청구서 확정**: 지난달 청구서도 매번 다시 계산합니다. 월이 끝날 때 금액을 고정해 저장하는 단계가 없습니다.
- **취소·반품분**: 발송 후 반품과 그에 따른 차감, 재고 복귀가 없습니다.
- **실물 대조 기록**: 보유 재고 숫자만 보여 주고, 대조 결과나 차이(분실, 파손)를 기록하는 기능은 없습니다.
- **미납 처리 실행**: 안내 발송, 스토어 이용 제한이 실제로 동작하지 않습니다.
- **최저 판매가를 올렸을 때**: 셀러가 상품을 등록하거나 판매가를 바꿀 때는 최저 판매가 미만을 막습니다 (셀러 어드민의 스토어 상품 관리). 하지만 운영자가 나중에 최저 판매가를 올려도 이미 등록된 상품의 판매가는 그대로입니다. 처음부터 스토어에 있던 기본 상품도 검사하지 않습니다.
- **가입 신청 접수 화면, 운영자 로그인과 권한**: 없습니다.
