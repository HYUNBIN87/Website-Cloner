# 셀러 어드민 (초안)

셀러가 주문을 확인하고, 입금을 확인하고, 발송하고, 공급 재고와 매출을 보고, 스토어 설정을 바꾸는 화면입니다.

- 작성일: 2026-11-23
- 상태: **초안**. 원본 사이트의 어드민은 아직 보지 못했습니다. 화면은 원본을 따라 만든 것이 아니라 [비즈니스 모델](business-model.md)과 [스토어 설정](../research/livemarket/store-settings.md) 문서를 기준으로 새로 만든 것입니다. 원본 어드민을 확인하면 구성이 바뀔 수 있습니다.
- 경로: `/seller-admin` 아래
- 디자인: 소비자 화면의 500px 컬럼, 카드, 상태 칩, 바텀 시트, 버튼 색·간격을 그대로 재사용했습니다.

## 지금 되는 것과 안 되는 것

- **전부 가짜 데이터입니다.** 고객 이름, 연락처, 주소, 입금자명, 송장번호, 공급 상품, 공급가, 이용료 플랜 모두 지어낸 값입니다.
- **이 브라우저의 localStorage에만 저장됩니다.** 서버, 은행(입금 내역), 결제, 택배사 연동은 없습니다. 다른 기기나 다른 브라우저에서는 보이지 않습니다.
- **셀러 로그인이 없습니다.** 주소를 아는 누구나 열 수 있습니다. 실제 서비스 전에 셀러 인증을 붙여야 합니다.
- 스토어는 데모샵 하나만 있습니다.

## 화면 구성

위쪽 메뉴에 여섯 개가 있습니다.

| 메뉴 | 경로 | 하는 일 |
| --- | --- | --- |
| 주문 목록 | `/seller-admin` | 들어온 주문서 전체를 상태별로 봄 |
| 입금 확인 | `/seller-admin/deposit` | 입금을 기다리는 주문을 모아 보고 입금 확인 처리 |
| 발송 처리 | `/seller-admin/shipping` | 결제완료 주문을 모아 보고 송장번호 입력 |
| 공급 재고 | `/seller-admin/inventory` | 공급 상품의 받은 수량, 판 수량, 남은 수량 |
| 매출 | `/seller-admin/sales` | 이번 달 매출과 청구 예정 금액 |
| 설정 | `/seller-admin/settings` | 스토어 설정 값 변경 |

### 1. 주문 목록
- 상태 필터: 전체 / 미결제 / 입금확인요청 / 결제완료 / 발송완료 / 취소. 각 필터에 건수를 표시합니다.
- "취소"에는 취소된 주문과 결제 기한이 지난 주문(기한 만료)이 함께 들어갑니다.
- 주문 카드: 상태, 주문 시각, 주문자명(닉네임), 입금자명, 품목(상품명·옵션·수량, 공급 상품은 "공급" 표시), 금액(상품 금액 + 배송비), 주문서 번호.
- 주문을 누르면 주문서 상세 시트가 열립니다. 주문서 번호, 주문 시각, 결제 마감, 주문자·연락처, 배송지, 요청사항, 품목, 입금받을 금액이 나오고, 상태에 따라 입금 확인이나 발송 처리를 여기서 합니다.

### 2. 입금 확인
- 목록: 입금확인요청 주문이 먼저, 그다음 미결제 주문.
- 주문서 상세의 "입금" 칸에 주문자명과 입금자명을 나란히 보여 줍니다.
- **입금자명이 주문자명과 다르면** 목록 카드에 빨간 "입금자명 다름" 배지가 붙고, 상세에서 입금자명 칸이 빨간 테두리로 바뀌며 금액을 확인하라는 경고가 나옵니다.
- "입금 확인" 버튼을 누르면 주문이 결제완료로 바뀝니다. 입금자명이 다르거나 입금 내역이 없는 주문은 확인 문구에 체크해야 버튼이 눌립니다.
- 소비자 화면에서 담은 주문(데모 계정)을 입금 확인하면 소비자의 주문내역에서도 결제완료로 바뀝니다.

### 3. 발송 처리
- 목록: 결제완료 주문, 오래된 주문부터.
- 주문서 상세에서 택배사를 고르고 송장번호(숫자와 `-`, 9~20자)를 입력해 "발송 처리"를 누르면 발송완료로 바뀝니다.
- **이 시점에 판매가 확정됩니다** (비즈니스 모델 3장). 공급 상품이 들어 있으면 그 수량이 공급 재고의 "판 수량"과 이번 달 청구 예정 금액에 반영됩니다. 발송 전에 그 안내가 표시됩니다.

### 4. 내 공급 재고
- 운영자에게 받은 공급 상품별로 공급가, 최저 판매가, 받은 수량, 판 수량, 회수 수량, 남은 수량을 보여 줍니다.
- 남은 수량 = 받은 수량 − 판 수량 − 회수 수량. 화면에서 입력하지 않고 자동 계산합니다.
- 판 수량은 발송완료된 주문의 수량입니다. 결제완료지만 발송 전인 수량은 "발송을 기다리는 수량"으로 따로 표시하고, 남은 수량보다 많으면 경고합니다.
- 받은 수량과 회수 수량은 운영자 어드민에서 기록할 값이라, 지금은 고정된 가짜 값입니다.

### 5. 내 매출
- 이번 달에 **발송 처리한** 주문 기준입니다. 결제완료지만 발송하지 않은 주문은 포함하지 않습니다.
- 매출: 발송 완료 건수, 상품 매출, 받은 배송비, 합계.
- 이번 달 청구 예정 금액 = 월 이용료 + 공급 대금(공급 상품별 발송 수량 × 공급가). 상품별 내역을 함께 보여 줍니다.
- 취소·반품분 차감은 아직 없습니다 (발송 후 반품 기능이 없음).

### 6. 스토어 설정
- [스토어 설정 문서](../research/livemarket/store-settings.md)의 모든 항목을 바꿀 수 있습니다: 결제 기한, 배송비(기본·무료배송 기준·도서산간), 취소찬스 횟수, 1회 주문 최대 수량, 주문서 합치기, 입금 계좌, 스토어 공지, 입장 안내 3단계, 소개글, SNS 링크, 고객센터 연락처, 발송지·반품지.
- "저장"을 누르면 소비자 화면(스토어 라이브 홈, 라이브 방, 옵션 시트, 결제 시트)에 바로 반영됩니다.
- "기본값으로 되돌리기"는 저장한 값을 지우고 `store-settings.ts`의 기본값으로 돌아갑니다.
- **이미 들어온 주문은 바뀌지 않습니다.** 결제 마감 시각, 배송비, 무료배송 기준은 주문할 때 주문에 저장되므로, 설정을 바꿔도 새 주문부터 적용됩니다.

## 주문 상태

| 상태 | 뜻 | 바뀌는 때 |
| --- | --- | --- |
| 미결제 | 주문서가 들어왔고 아직 입금 확인 전 | 고객이 주문서에 담을 때 |
| 입금확인요청 | 고객이 "입금완료 확인요청"을 누름 | 고객이 요청할 때 |
| 결제완료 | 셀러가 입금을 확인함 | 셀러가 "입금 확인"을 누를 때 |
| 발송완료 | 송장번호가 입력됨. 판매 확정 | 셀러가 "발송 처리"를 누를 때 |
| 취소 | 주문서 취소 | (초안에는 취소 기능 없음. 가짜 주문 1건) |
| 기한 만료 | 미결제인 채 결제 마감이 지남 | 저장된 마감 시각이 지나면 자동 |

## 아직 없는 것, 정해야 할 것

- **입금자명의 출처**: 지금은 가짜 값입니다. 실제로는 은행 입금 내역 연동으로 받을지, 셀러가 직접 입력할지 정해야 합니다. 입금액과 주문 금액의 자동 대조도 그에 달려 있습니다.
- **주문 취소**: 셀러가 주문서를 취소하는 기능이 없습니다. 취소찬스 차감 규칙과 함께 정해야 합니다.
- **되돌리기**: 입금 확인이나 발송 처리를 잘못했을 때 되돌리는 기능이 없습니다.
- **발송 후 반품**: 반품 처리, 재고 복귀, 청구 금액 차감이 없습니다 (비즈니스 모델 7장의 남은 질문).
- **기한 만료된 주문에 뒤늦게 입금된 경우**: 지금은 입금 확인을 할 수 없습니다.
- **일괄 처리**: 여러 주문의 입금 확인, 송장번호 일괄 입력(엑셀 업로드 등)이 없습니다.
- **검색·기간 필터·페이지 나누기**: 주문이 적어 넣지 않았습니다.
- **스토어 설정 입력 검증**: 숫자는 0 이상 정수(최대 수량과 N분은 1 이상)로 보정하지만, 계좌번호나 링크 형식은 확인하지 않습니다.
- **운영자 어드민**: 공급 출고 기록, 회수 처리, 월 청구서 화면은 아직 없습니다. 그래서 받은 수량·회수 수량·이용료가 고정값입니다.
- **셀러 로그인과 권한**: 없습니다.
