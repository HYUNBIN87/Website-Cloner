# 셀러 어드민 (초안)

셀러가 주문을 확인하고, 입금을 확인하고, 발송하고, 공급 재고와 매출을 보고, 스토어 설정을 바꾸는 화면입니다.

- 작성일: 2026-11-23
- 상태: **초안**. 원본 사이트의 어드민은 아직 보지 못했습니다. 화면은 원본을 따라 만든 것이 아니라 [비즈니스 모델](business-model.md)과 [스토어 설정](../research/livemarket/store-settings.md) 문서를 기준으로 새로 만든 것입니다. 원본 어드민을 확인하면 구성이 바뀔 수 있습니다.
- 경로: `/seller-admin` 아래
- 디자인: 소비자 화면의 500px 컬럼, 카드, 상태 칩, 바텀 시트, 버튼 색·간격을 그대로 재사용했습니다.

## 지금 되는 것과 안 되는 것

- **전부 가짜 데이터입니다.** 고객 이름, 연락처, 주소, 입금자명, 송장번호, 공급 상품, 공급가, 이용료 플랜 모두 지어낸 값입니다.
- **이 브라우저의 localStorage에만 저장됩니다.** 서버, 은행(입금 내역), 결제, 택배사 연동은 없습니다. 다른 기기나 다른 브라우저에서는 보이지 않습니다.
- **셀러 로그인이 없습니다.** 주소를 아는 누구나 열 수 있습니다. 실제 서비스 전에 셀러 인증을 붙여야 합니다.
- 스토어는 데모샵 하나만 있습니다.

### 1. 주문 목록
- 상태 필터: 전체 / 미결제 / 입금확인요청 / 결제완료 / 발송완료 / 취소. 각 필터에 건수를 표시합니다.
- "취소"에는 취소된 주문과 결제 기한이 지난 주문(기한 만료)이 함께 들어갑니다.
- 주문 카드: 상태, 주문 시각, 주문자명(닉네임), 입금자명, 품목(상품명·옵션·수량, 공급 상품은 "공급" 표시), 금액(상품 금액 + 배송비), 주문서 번호.
- 주문을 누르면 주문서 상세 시트가 열립니다. 주문서 번호, 주문 시각, 결제 마감, 주문자·연락처, 배송지, 요청사항, 품목, 입금받을 금액이 나오고, 상태에 따라 입금 확인이나 발송 처리를 여기서 합니다.

### 2. 입금 확인
- 목록: 입금확인요청 주문이 먼저, 그다음 미결제 주문.
- 주문서 상세의 "입금" 칸에 주문자명과 입금자명을 나란히 보여 줍니다.
- **입금자명이 주문자명과 다르면** 목록 카드에 빨간 "입금자명 다름" 배지가 붙고, 상세에서 입금자명 칸이 빨간 테두리로 바뀌며 금액을 확인하라는 경고가 나옵니다.
- "입금 확인" 버튼을 누르면 주문이 결제완료로 바뀝니다. 입금자명이 다르거나 입금 내역이 없는 주문은 확인 문구에 체크해야 버튼이 눌립니다.
- 소비자 화면에서 담은 주문(데모 계정)을 입금 확인하면 소비자의 주문내역에서도 결제완료로 바뀝니다.

### 입금 자동매칭
은행 입금 내역을 미결제 주문과 자동으로 맞춰 보는 화면입니다. **실제 은행 연동은 아직 없습니다.** 화면과 매칭 로직만 있고, 입금 내역 8건은 가짜 데이터입니다.

- **입금 받는 은행**: 셀러가 쓰는 은행을 고르거나 직접 입력하고 계좌번호를 저장합니다. 처음에는 스토어 설정의 입금 계좌가 들어 있습니다. 은행 목록도 가짜 이름입니다. 저장해도 입금 내역이 바뀌지는 않습니다.
- **입금 내역**: 입금자명, 금액, 입금 시각. 최근 순입니다.
- **자동 매칭 결과**: 입금 건마다 아래 넷 중 하나로 표시합니다.

| 결과 | 기준 | 처리 |
| --- | --- | --- |
| 매칭됨 | 입금자명이 주문자명과 같고 금액이 주문 금액과 같은 미결제 주문이 있음 | "한 번에 입금 확인" 대상 |
| 금액 불일치 | 입금자명이 같은 미결제 주문은 있지만 금액이 다름 | 자동 처리하지 않음. 주문 금액, 입금액, 부족/초과 금액을 보여 줌 |
| 미매칭 | 입금자명이 같은 미결제 주문이 없음 | 자동 처리하지 않음. 금액이 같은 미결제 주문이 있으면 후보로 보여 줌 |
| 확인 완료 | 이미 결제완료·발송완료인 주문의 입금 | 처리할 것 없음 |

- **매칭 규칙**: 입금 한 건은 주문 한 건에만, 주문 한 건은 입금 한 건에만 맞춥니다. 오래된 입금과 오래된 주문부터 맞춥니다. 이름은 완전히 같아야 합니다. 닉네임이 붙은 입금자명("박가상민트라떼")은 미매칭이 됩니다.
- **한 번에 입금 확인**: "매칭된 N건 한 번에 입금 확인" 버튼을 누르면 매칭된 주문이 모두 결제완료로 바뀝니다. 어느 입금으로 확인했는지 주문에 함께 저장합니다.
- **미입금**: 입금 내역에서 짝을 찾지 못한 미결제 주문을 따로 모아 보여 줍니다. 고객이 입금완료 확인요청을 했는데 입금 내역이 없는 주문, 같은 금액의 미매칭 입금이 있는 주문은 그 사실을 표시합니다.
- 금액 불일치와 미매칭 건은 주문서를 열어 "입금 확인" 화면과 같은 방식으로 직접 확인합니다.
- 주문 목록의 "입금자명"은 이 매칭과 이어져 있습니다. 주문에 알려진 입금자명이 없으면 매칭된 입금의 이름을 보여 줍니다.

**입금 내역을 읽어오는 방식은 정하지 않았습니다.** 은행 입금 알림 문자 파싱, 오픈뱅킹 API, 은행 사이트 스크래핑 중 무엇으로 할지는 서버를 만드는 단계에서 정합니다. 그때 정해야 할 것은 아래와 같습니다.

- 어떤 방식을 쓸지, 은행별로 지원 범위가 어떻게 다른지
- 셀러의 계좌 인증 정보를 어디에 어떻게 보관할지
- 입금 내역을 얼마나 자주 가져올지, 같은 입금이 두 번 들어오지 않게 어떻게 구분할지
- 입금자명 표기 차이(공백, 닉네임 추가, 글자 수 제한으로 잘린 이름)를 어디까지 같은 이름으로 볼지
- 한 고객이 여러 주문 금액을 합쳐서 한 번에 입금한 경우의 처리

### 3. 발송 처리
- 목록: 결제완료 주문, 오래된 주문부터.
- 주문서 상세에서 택배사를 고르고 송장번호(숫자와 `-`, 9~20자)를 입력해 "발송 처리"를 누르면 발송완료로 바뀝니다.
- **이 시점에 판매가 확정됩니다** (비즈니스 모델 3장). 공급 상품이 들어 있으면 그 수량이 공급 재고의 "판 수량"과 이번 달 청구 예정 금액에 반영됩니다. 발송 전에 그 안내가 표시됩니다.

### 스토어 상품 관리
셀러가 자기 스토어에서 팔 상품을 등록하는 화면입니다. 등록한 상품은 **스토어 상품 목록(`/{store}/profile-live`)과 라이브 방 상품 목록에 바로 나타나고**, 고객이 주문서에 담을 수 있습니다.

- **공급 상품 등록**: 운영자에게 받은 공급 상품 중 아직 스토어에 없는 것을 골라 판매가를 정해 등록합니다. 고를 수 있는 것은 운영자 어드민의 공급 출고 기록에서 이 셀러에게 넘긴 상품뿐입니다.
- **판매가는 최저 판매가 이상만 됩니다.** 그 아래로 입력하면 등록되지 않고 오류가 나옵니다. 등록한 뒤 판매가를 바꿀 때도 같은 규칙으로 막습니다. 화면에서만 막는 것이 아니라 저장하는 쪽에서 검사합니다.
- **자체 상품 등록**: 운영자에게 공급받지 않은 내 상품을 상품명과 판매가로 등록합니다. 공급 대금이 청구되지 않습니다. 사진 등록은 없어 기본 아이콘으로 표시됩니다.
- 상품명은 스토어 안에서 겹칠 수 없습니다. 주문 품목을 상품명으로 구분하기 때문입니다. 자체 상품에 공급 상품과 같은 이름도 쓸 수 없습니다.
- **내가 등록한 상품**: 공급/자체 구분, 판매가, 판매가 변경, 판매 중지. 판매 중지하면 상품 목록에서 사라지고, 이미 들어온 주문의 품목은 그대로 남습니다.
- **기본 상품**: 처음부터 스토어에 있던 상품 목록입니다. 초안에서는 수정하거나 판매 중지할 수 없습니다.
- **공급가는 셀러에게만 보입니다.** 이 화면에는 공급가, 최저 판매가, 개당 내 몫(판매가 − 공급가)이 나오지만, 스토어에 등록되는 상품 정보에는 상품명, 판매가, 사진만 들어갑니다. 고객 화면이 받는 데이터에 공급가가 없습니다.
- 공급 상품을 등록해 팔고 발송 처리하면, 그 수량이 공급 재고의 판 수량과 청구 예정 금액에 반영됩니다.

단, 지금은 서버가 없어 운영자 데이터(공급가 포함)가 같은 브라우저의 localStorage에 들어 있습니다. 고객 화면에는 표시되지 않지만, 실제로 공급가를 고객에게서 분리하려면 서버에서 고객용 응답에 공급가를 넣지 않아야 합니다.

### 방송 관리
셀러가 라이브와 타임딜 방송을 만들고 운영하는 화면입니다. **"진행 중"인 방송이 손님의 라이브 방에 나옵니다.**

- **방송 만들기**: 방송 종류(라이브 / 타임딜), 제목, 시작 일시, 유튜브 영상 ID(선택, 11자), 판매할 상품, 비밀 라이브방 설정. 만들면 "예정" 상태가 됩니다.
- **판매할 상품**: 스토어 상품(기본 상품 + 스토어 상품 관리에서 등록한 상품) 중에서 고릅니다. 1개 이상 골라야 합니다. 라이브 방의 상품 목록과 상품 수에는 고른 상품만 나옵니다.
- **방송 상태**: 예정 → (방송 시작) → 진행 중 → (방송 종료) → 종료. 진행 중인 방송은 한 번에 하나뿐이라, 다른 방송이 진행 중이면 시작할 수 없습니다. 예정인 방송은 삭제할 수 있고, 예정·진행 중인 방송은 수정할 수 있습니다. 종료된 방송은 바꿀 수 없습니다.
- **비밀 라이브방**: 켜기/끄기와 입장 조건(비밀번호 또는 단골만).
  - 비밀번호: 손님이 라이브 방에 들어갈 때 비밀번호를 묻습니다. 맞으면 그 브라우저 탭에서는 다시 묻지 않습니다.
  - 단골만: 로그인한 단골만 들어갑니다. 초안에서는 데모 계정이 이 스토어의 단골이라, 로그인하지 않은 손님에게만 안내와 로그인 버튼이 나옵니다.
  - 꺼져 있으면 누구나 들어갑니다. 스토어 화면의 "비밀 라이브방 입장" 문구는 원본 화면 그대로라 켜고 끄는 것과 상관없이 같습니다.
- **방송별 주문·매출 요약**: 방송마다 주문 수, 결제완료 건수, 매출(결제완료·발송완료 주문의 상품 금액 합계, 배송비 제외).

손님 화면에 반영되는 것:

| 손님 화면 | 따라가는 방송 정보 |
| --- | --- |
| 라이브 방 상단 제목, 스토어 화면의 방송 제목 | 진행 중인 방송의 제목 |
| 라이브 방 영상, 스토어 화면 영상 | 진행 중인 방송의 유튜브 영상 ID (비어 있으면 "LIVE 영상 영역" 표시) |
| 라이브 방 상품 목록과 상품 수 | 방송에서 고른 판매 상품 |
| 라이브 방 입장 | 비밀 라이브방 설정 |
| 주문내역 카드의 "⏰ yy.MM.dd HH:mm 타임딜" / "🔴 yy.MM.dd HH:mm 라이브" | 주문한 방송의 종류와 시작 일시 |
| 주문서의 "yyyy.MM.dd. HH:mm 시작 타임딜" + 제목, 결제 시트 제목("타임딜 주문 결제" / "라이브 주문 결제") | 주문한 방송의 종류, 시작 일시, 제목 |
| 입장 안내("라이브 입장 전 필독")를 다시 보여 줄지 | 방송마다 한 번 |

- 진행 중인 방송이 없으면 라이브 방에는 "진행 중인 방송이 없습니다" 안내가, 스토어 화면에는 "방송 준비 중"이 나옵니다.
- **주문서의 방송 정보는 주문할 때 주문에 복사합니다.** 방송 제목이나 시작 일시를 나중에 고쳐도 이미 들어온 주문서는 바뀌지 않습니다. 결제 마감, 배송비와 같은 방식입니다.
- 주문서 합치기는 같은 방송 안에서만 합니다. 방송이 바뀌면 새 주문서가 됩니다.
- 예전 화면에 있던 "타임딜 N회차" 표시는 시작 일시 + 제목 표시로 이미 바뀌었고, 회차 번호는 따로 관리하지 않습니다.

**비밀 라이브방은 실제 접근 제어가 아닙니다.** 비밀번호를 브라우저에 그대로 저장하고 브라우저에서 비교합니다. 실제로 막으려면 서버에서 확인해야 합니다. 단골 여부도 지금은 로그인 여부만 봅니다.

### 4. 내 공급 재고
- 운영자에게 받은 공급 상품별로 공급가, 최저 판매가, 받은 수량, 판 수량, 회수 수량, 남은 수량을 보여 줍니다.
- 남은 수량 = 받은 수량 − 판 수량 − 회수 수량. 화면에서 입력하지 않고 자동 계산합니다.
- 판 수량은 발송완료된 주문의 수량입니다. 결제완료지만 발송 전인 수량은 "발송을 기다리는 수량"으로 따로 표시하고, 남은 수량보다 많으면 경고합니다.
- 받은 수량과 회수 수량은 [운영자 어드민](operator-admin.md)의 공급 출고 기록과 회수 처리에서 온 값입니다. 운영자가 기록하면 여기 숫자가 바뀝니다.

### 5. 내 매출
- 이번 달에 **발송 처리한** 주문 기준입니다. 결제완료지만 발송하지 않은 주문은 포함하지 않습니다.
- 매출: 발송 완료 건수, 상품 매출, 받은 배송비, 합계.
- 이번 달 청구 예정 금액 = 월 이용료 + 공급 대금(공급 상품별 발송 수량 × 공급가) − 취소·반품분. 상품별 내역과 결제일을 함께 보여 줍니다. 운영자 어드민의 이번 달 청구서와 같은 계산이라 금액이 같고, 월 이용료와 결제일은 운영자가 지정한 플랜을 따릅니다.
- 취소·반품분 차감은 아직 없습니다 (발송 후 반품 기능이 없음).

### 6. 스토어 설정
- [스토어 설정 문서](../research/livemarket/store-settings.md)의 모든 항목을 바꿀 수 있습니다: 결제 기한, 배송비(기본·무료배송 기준·도서산간), 취소찬스 횟수, 1회 주문 최대 수량, 주문서 합치기, 입금 계좌, 스토어 공지, 입장 안내 3단계, 소개글, SNS 링크, 고객센터 연락처, 발송지·반품지.
- "저장"을 누르면 소비자 화면(스토어 라이브 홈, 라이브 방, 옵션 시트, 결제 시트)에 바로 반영됩니다.
- "기본값으로 되돌리기"는 저장한 값을 지우고 `store-settings.ts`의 기본값으로 돌아갑니다.
- **이미 들어온 주문은 바뀌지 않습니다.** 결제 마감 시각, 배송비, 무료배송 기준은 주문할 때 주문에 저장되므로, 설정을 바꿔도 새 주문부터 적용됩니다.

## 아직 없는 것, 정해야 할 것

- **입금 내역의 출처**: 지금은 가짜 값입니다. 문자 파싱, 오픈뱅킹, 스크래핑 중 어떤 방식으로 읽어올지는 서버 단계에서 정합니다 ("입금 자동매칭" 참고).
- **주문 취소**: 셀러가 주문서를 취소하는 기능이 없습니다. 취소찬스 차감 규칙과 함께 정해야 합니다.
- **되돌리기**: 입금 확인이나 발송 처리를 잘못했을 때 되돌리는 기능이 없습니다.
- **발송 후 반품**: 반품 처리, 재고 복귀, 청구 금액 차감이 없습니다 (비즈니스 모델 7장의 남은 질문).
- **기한 만료된 주문에 뒤늦게 입금된 경우**: 지금은 입금 확인을 할 수 없습니다.
- **상품 정보**: 사진 등록, 상품 설명, 옵션(컬러·사이즈), 스토어 재고 수량, 기본 상품의 수정·판매 중지가 없습니다. 옵션은 모든 상품이 같은 가짜 옵션을 씁니다.
- **재고보다 많은 주문**: 공급 상품의 남은 수량을 넘는 주문을 막지 않습니다 (비즈니스 모델 7장의 남은 질문).
- **방송**: 시작 일시가 되어도 자동으로 시작·종료하지 않습니다(버튼으로만). 실제 송출, 시청자 수, 채팅 관리, 방송 중 상품 고정(핀) 변경, 다시보기 시각 설정이 없습니다. 단골 맺기 기능이 없어 "단골만"은 로그인 여부로 대신합니다.
- **일괄 처리**: 여러 주문의 입금 확인, 송장번호 일괄 입력(엑셀 업로드 등)이 없습니다.
- **검색·기간 필터·페이지 나누기**: 주문이 적어 넣지 않았습니다.
- **스토어 설정 입력 검증**: 숫자는 0 이상 정수(최대 수량과 N분은 1 이상)로 보정하지만, 계좌번호나 링크 형식은 확인하지 않습니다.
- **셀러 로그인과 권한**: 없습니다.
